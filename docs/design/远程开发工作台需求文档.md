# 远程开发工作台需求文档

版本：0.3\
日期：2026 年 10 月 26 日\
状态：产品方向已确认，详细需求待评审\
产品名称：远程开发工作台，暂作工作名称

本工具面向个人开发者，在统一的图形聊天与项目工作台中连接远端 Agent、管理项目，并支持 SSH 远端项目执行和云端 Agent 操作本机项目。首版适配 Claude Code 与 Codex，先发布 Windows，后续扩展 macOS、Linux 和团队能力。功能参考 RemoteShell 和 CC Desk Tunnel，整体布局与技术栈参考 Pymss Studio，聊天交互参考 CC Desk Tunnel、ChatGPT 与 Open WebUI 的常见形式，业务代码重新组织和实现。

## 1 已确认范围与后续决策

### 1.1 已确定的要求

1. 参考当前目录下两个项目的用途、核心功能与使用流程，编写一个独立工具。
2. 根据新工程的边界重新实现业务代码，不整库搬运或仅替换名称。
3. 使用 Pymss Studio 的前端布局与语言技术栈作为设计基线。
4. 当前阶段交付需求与交互设计文档，工程实现随后展开。
5. 首版同时支持 SSH 远程开发和云端 Agent 操作本机项目，统一在同一个工作台中。
6. 主交互为图形聊天与项目管理，原生终端作为辅助开发、安装与排障入口。
7. 首版接入 Claude Code 与 Codex，均须具备图形对话核心流程。
8. 首次公开发布面向 Windows，后续逐步补齐 macOS 和 Linux；从首版就隔离平台实现。
9. 首版面向个人，支持多服务器和多设备；团队共享与权限管理后续扩展。
10. 按未来公开到 GitHub、持续迭代和发布软件的方向组织工程与文档。
11. Claude Code 与 Codex 使用服务器上未修改的官方程序，由用户在服务器完成原生登录；桌面负责提示词和控制交互的转发、进度与结果展示，不直接调用模型 API 或重建 Agent 推理循环。

## 2 产品目标与基本概念

用户应能在一个桌面应用中选择连接、项目和 AI 工具，通过图形会话完成开发，需要时打开辅助终端，并明确知道项目文件和命令分别位于哪台设备。

产品提供两条执行路径：

| 方式 | 项目所在位置 | AI 与命令的执行位置 | 本机承担的职责 |
| --- | --- | --- | --- |
| SSH 远程开发 | Linux 服务器 | 同一台服务器 | SSH 连接、图形交互、文件浏览、编辑与传输、辅助终端 |
| 云端 AI 操作本机 | 用户本机 | AI 进程在 Linux 服务端，项目命令经反向通道在本机执行 | 项目选择、交互界面、临时执行组件与通道 |

两条路径都提供图形聊天。交互方式与“命令在哪执行”分别建模，终端以辅助面板存在。图形会话绑定一个 Agent、一个运行环境与一个执行目标；切换 Agent 时创建新会话，不直接互换 Claude 与 Codex 的原生上下文。终端能否共享图形会话的原生上下文必须逐工具验证。

| 概念 | 定义 |
| --- | --- |
| 连接配置 | 连接某台 SSH 服务器或某套代理服务的地址、身份与偏好 |
| 在线连接 | 某次实际建立的网络连接，可随断网结束或重建 |
| 设备 | 承担项目执行的电脑或服务器，具有稳定标识 |
| 项目 | 运行服务、设备与目录的组合；相同路径在不同服务或设备上分别建档 |
| 终端 | 连接远端或执行设备上一个 PTY 的交互视图 |
| 运行代理 | 应用自有的远端连接桥，负责持有官方进程、转发输入与控制、记录展示事件，不实现模型推理循环 |
| AI 会话 | AI 工具自己的上下文及对应索引，独立于某次网络连接 |
| 运行 | AI 会话中一次仍在执行、等待审批或等待后台任务的工作 |
| 工作台布局 | 当前资源栏、标签、分屏与选中项，只描述显示状态 |

首版定位为单用户工具，可以管理多台自己的设备和多个连接配置。团队协作、多租户、额度调度与共享账号不在当前基线中；公开发布不等于提供公共托管服务。

“桌面负责转发”描述业务与模型的边界。云端操作本机项目时，本机仍有必要的 SSH 与命令执行组件；模型请求和 Agent 决策继续发生在服务器上的官方 CLI 中。

## 3 功能来源与交付分组

交付分组用于安排实现顺序，不代表省略参考项目的其他能力。“首版”行均为公开版本必须实现的能力，“完整能力”行保留在路线中，具体版本节点见 D5。

| 分组 | 功能 | 来源 | 进入条件 |
| --- | --- | --- | --- |
| 基础工作台 | 标题栏、侧导航、路由、主题、设置、日志入口、草稿与快捷键 | Pymss Studio 与 CC Desk Tunnel | 首版必需 |
| 首版 SSH 开发 | 服务器列表、主机指纹确认、密码认证、目录与最近路径 | RemoteShell | 必需 |
| 首版 SSH 开发 | 辅助终端、多标签、最多四分屏、键盘与粘贴 | RemoteShell | 必需 |
| 首版 SSH 开发 | 文本编辑、目录管理、压缩与下载 | RemoteShell | 必需 |
| 首版 AI 环境 | 运行代理及 Claude、Codex 的依赖检测、安装确认、启动 | RemoteShell | 必需，按实际工具依赖检测 |
| 首版本机执行 | 服务凭据、证书信任、设备注册、临时 SSH、反向通道 | CC Desk Tunnel | 必需 |
| 首版本机执行 | 连接诊断、断线重连、任务宽限、事件补取 | CC Desk Tunnel | 必需 |
| 首版图形对话 | 项目与会话、流式内容、工具调用、审批、停止、原生恢复 | CC Desk Tunnel | 两个 Agent、两种执行方式均须通过 |
| 首版项目管理 | 项目配置、收藏、归档、搜索、会话关联与设备定位 | 两者扩展整合 | 必需 |
| 首版多连接 | 多服务器配置、多设备归属、目标明确与连接间隔离 | 两者 | 必需 |
| 会话增强 | 追加输入、分叉、编辑重发、压缩与高级上下文控制 | CC Desk Tunnel | 按原生工具能力验证并安排版本 |
| 完整能力 | 账号管理、推理细项、额度和调用统计 | CC Desk Tunnel | 基础认证首版具备，扩展管理与统计逐项纳入 |
| 完整能力 | 定时任务、托盘后台、通知 | CC Desk Tunnel | 核心开发流程验收后纳入 |
| 完整能力 | 跨设备实时操作已有会话、会话接管与迁移提示 | CC Desk Tunnel | 在首版多设备归属模型上逐步增强 |
| 完整能力 | 客户端与服务端升级、备份恢复、可选浏览器访问 | CC Desk Tunnel | 桌面和服务端基础流程稳定后纳入 |

完整功能目标应保留“原生工具能力不同”的事实。例如，CLI 启动成功不意味着已经支持图形分叉、额度查询或上下文压缩。界面只展示已实现且可验证的能力。

## 4 核心使用流程

### 4.1 通过 SSH 操作服务器项目

1. 在“连接”页面新增 SSH 连接，填写地址、端口、用户名和密码。
2. 首次连接展示主机指纹，由用户确认后保存；已有指纹变化时中止连接。
3. 连接成功后显示远端目录，用户选择项目目录；列表提供该连接最近使用的目录。
4. 若目标未准备图形运行代理，展示需要安装的组件，由用户发起安装。代理已存在时可以启动已有组件，不每次重新安装。
5. 检查服务器上官方 CLI 的登录状态；未登录时提供原生登录入口，由用户完成官方流程，凭据留在服务器。
6. 在项目下选择 Claude 或 Codex 并创建图形会话。连接桥与官方 Agent 都在远端，文件和开发命令也在远端项目内执行。
7. 通过资源栏浏览文件、打开文本编辑器、执行下载或目录管理；需要时打开辅助 Shell 或官方 CLI 终端。
8. 关闭某个标签只影响该标签对应的资源；断开连接前列出会受影响的终端、运行和未保存文件。

SSH 登录成功只表示能够访问服务器。图形聊天还需要远端运行代理与对应 Agent 就绪；这两个状态分别呈现。

SSH 登录与代理服务登录使用不同表单。选择一种连接类型后，只要求填写该类型需要的字段。

### 4.2 云端 AI 操作本机项目

1. 添加代理服务地址、服务凭据和必要的证书指纹。
2. 客户端校验服务端身份，通过认证后准备本机临时执行组件。
3. 本机只监听回环地址，主动向代理服务建立执行通道；通过真实探测后显示“执行通道已就绪”。
4. 用户选择本机项目，再选择服务器上已完成原生登录的 Claude 或 Codex，创建或恢复绑定该设备的图形会话；未登录时提供官方登录入口。
5. 云端 AI 经通道操作项目，客户端展示结构化内容、工具活动和审批。界面持续显示当前执行设备和目录，需要时打开辅助终端。
6. 网络中断时分别展示控制连接、执行通道和运行状态；恢复连接后补取历史事件，不自动重发未收到确认的写操作。
7. 用户主动断开时明确说明受影响的运行，并停止属于该连接的临时组件。

辅助 CLI 终端若要在网络中断后保留同一个 PTY，需要专门的保活方案；不把图形会话的持久化能力直接套用到终端。

### 4.3 AI 工具未安装

检测结果区分“未安装”“已安装”“检测失败”和“版本未知”。用户点击未安装工具后，先看到安装目标、操作内容和依赖，再确认执行；安装日志进入终端或任务详情。失败后保留原因，并允许重试。

不因连接服务器、进入页面或检测环境而自动安装软件、申请账号或修改远端 Shell 配置。

## 5 页面与信息架构

页面壳与 Pymss Studio 对齐，页面内的信息根据远程开发任务重新组织。聊天采用会话列表、消息区、底部输入框的常见交互。详细尺寸与交互见[前端布局与交互规范](./前端布局与交互规范.md)。

| 页面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 工作台 | 当前项目与执行目标、会话列表、聊天正文、工具活动和辅助资源面板 | 发送消息、审批、停止、打开终端、编辑与保存 |
| 连接 | SSH 服务器与代理服务分组，连接状态与最近使用时间 | 新增、编辑、连接、断开、删除配置 |
| 项目 | 按连接和设备分组的目录、收藏与最近项目 | 打开、选择目录、改名、移除索引 |
| 任务 | 安装、传输和已纳入范围的定时任务 | 查看详情、取消、重试 |
| 环境 | 当前目标上的工具、依赖、版本与可用能力 | 检测、查看安装方案、启动 |
| 诊断 | 连接阶段、运行组件、重要错误和可导出日志 | 重试、打开日志目录、导出脱敏记录 |
| 设置 | 外观、语言、快捷键、终端、存储、连接偏好、升级 | 保存、恢复对应项默认值 |

侧导航上方放业务入口，下方固定诊断和设置。“任务”页面内提供传输记录，避免为少量能力增加重复导航入口。未纳入首版的业务不展示空入口。

工作台默认左侧为项目与会话列表，中间为聊天正文与底部输入框，右侧文件与工具详情按需展开；辅助终端置于底部抽屉或独立工作标签。切换到专注终端视图后可以使用多标签与四分屏，避免默认聊天页被终端布局挤占。

## 6 功能要求

### FR01 连接配置与凭据

- 配置具有稳定标识和用户可读名称。修改名称不改变项目、最近目录和任务的关联。
- SSH 首版使用密码认证，与 RemoteShell 对齐；私钥认证单独列为扩展候选，不隐含在“支持 SSH”中。
- 默认不保存密码；保存时使用操作系统的受保护存储。无安全存储能力时禁用保存，并给出明确原因。
- 服务凭据与 AI 账号凭据分别管理，密码和令牌不进入 URL、普通配置导出与运行日志。
- Agent 认证由服务器上的官方 CLI 管理。桌面不自建 Claude 或 Codex 账号登录服务、不复制官方令牌，也不将已登录的 CLI 静默改为其他计费或认证方式。
- 删除连接配置时不删除服务器项目；本地关联索引的保留或清理范围须在操作前说明。

### FR02 项目与文件

- 项目由运行服务、执行设备与规范化目录共同确定；跨服务导入同一物理目录时保留各自上下文归属，提供潜在并发写入提示。
- 最近目录按连接和远端用户隔离；最近目录可参考 RemoteShell 保留八条，容量可以在详细设计时调整。
- 支持目录刷新、新建目录、文件与目录删除、打包下载；破坏性操作展示目标路径并要求确认。
- 文件操作请求绑定发起时的连接、设备和路径；用户切换项目后，迟到的结果不得应用到新项目。
- 下载保存到用户选择的本机目录；重名时保留原文件并提供改名或明确覆盖选项。
- 展示传输进度、结果与失败原因。重试不重复创建不可辨识的结果文件。

### FR03 原生终端与分屏

- 支持 Shell 和已纳入范围的 AI CLI，按当前项目目录启动。
- 支持多标签、关闭标签、标签切换和最多四分屏。关闭分屏保留标签，关闭终端标签则结束对应终端资源。
- 支持终端尺寸同步、Unicode、ANSI 颜色、常见光标控制和 bracketed paste。
- 业务快捷键与终端按键有明确优先级。输入焦点在终端时，常用 CLI 组合键正常传递；全局快捷键可查看和调整。
- 终端搜索、回滚缓存和复制操作属于本机显示能力；不将终端画面解析成 AI 图形对话协议。
- 首次实现要用真实 Codex、Claude CLI 验证输入、中文、粘贴、窗口缩放和退出，不能仅用普通 Shell 输出代替验收。

### FR04 文本编辑

- 打开远端 UTF-8 文本；首版大小上限为 2 MiB，与 RemoteShell 对齐。本机项目中的编辑操作也必须通过明确的项目目标访问。
- 支持基本编辑、保存、未保存标识和关闭确认；保留原换行格式及文件权限。
- 保存失败时保留编辑器内的完整内容，并展示可用于恢复的具体位置或处理方式。
- 检测到远端文件已变化时，提示重新读取或明确覆盖，不静默覆盖外部修改。
- 撤销、搜索与语法高亮不默认视为参考项目已有能力；是否纳入首版由实现计划单独确定。

### FR05 环境检测与安装

- 分别检测 Agent 运行环境与项目执行设备：官方 CLI、运行代理和实际采用的适配依赖在 Linux 运行端检测；本机执行方式中的 SSH、脚本解释器等在本机检测，显示检测时间与目标。
- 支持已确认工具的可执行位置、版本和可用状态；失败不伪装为“未安装”。
- 安装由用户明确发起，展示依赖和目标。安装失败可查看关键日志，取消后清理归属明确的进程。
- 安装结束重新检测；退出码为零但工具仍不可用时，不显示安装成功。

### FR06 反向执行通道

- 本机主动连接，外部入口复用同一服务地址；本机组件仅监听回环地址。
- 每次连接生成临时身份和通道密钥，先验证服务端身份，再发送敏感信息。
- 通道仅转发 SSH 字节；原生 SSH 负责认证和传输，避免再定义一套远程命令语言。
- 本机组件随连接生命周期启动和回收；退出、失败与重连均有明确的清理路径。
- 执行通道必须通过真实命令探测，不能只凭 WebSocket 已连通宣布可用。
- 当前授权按用户权限执行，项目目录用于定位工作，不宣称具有项目级沙箱隔离。

### FR07 图形 AI 会话

本节为首版主流程，Claude 与 Codex 均须覆盖创建会话、流式输出、工具活动、审批、停止和原生恢复。

- 按项目组织会话，支持创建、改名、搜索、删除、恢复，并展示运行状态。
- 流式展示助手内容、工具调用、原生公开的思考摘要、错误、审批和用户提问。
- 首版支持停止与原生可用模型的选择。停止的结果按实际观察展示，不承诺撤销已执行命令。
- 追加输入、分叉、编辑重发、推理细项和压缩属于增强批次，使用原生公开能力；未支持的工具隐藏对应入口。
- 审批模式来自对应 AI 工具，保留人工处理原生请求的入口；应用不另外生成一套 AI 审批结果。
- 原生会话记录是模型上下文的权威；展示历史不能代替原生上下文。缺失时明确报错并提供恢复路径。
- 每个工具维护可验证的能力列表。增强功能缺失时可以隐藏对应入口，但不能用“仅提供 CLI 终端”替代已约定的双 Agent 图形主流程。
- 展示模型、推理强度、上下文和用量时，保留各 Agent 自己的语义；未返回实际读数时不显示伪造的百分比。

### FR08 重连与请求一致性

- 界面区分配置、控制连接、执行通道与运行状态，不能用一个“在线”标签替代所有状态。
- 图形运行归属于运行服务与原生会话，不随某条 SSH 转发或控制连接被动销毁；运行代理以可管理的进程或服务持有 Agent，启动方式在部署设计中明确。
- 自动重连使用有上限的退避间隔，用户可停止；认证被拒绝或版本不兼容时不持续重试。
- 图形会话用事件序号补取和去重。读取请求可以重试；未获确认的消息发送、删除、安装和文件写入不自动重放。
- 云端图形运行可参考 CC Desk Tunnel 保留五分钟离线宽限。恢复后继续使用原生会话，超时后明确标记中断。
- 首版普通 SSH 终端默认在连接失效后结束，不承诺进程保活；若需要保活，将其作为独立验收项设计。
- 断线期间只保留既有草稿和编辑内容，不向错误或已切换的设备补发操作。

### FR09 数据与恢复

- 本机保存连接索引、项目索引、设置、草稿及布局；秘密进入系统凭据存储。
- 云端按需保存会话索引、展示事件和原生 AI 数据；临时连接数据与长期上下文分开管理。
- AI 认证凭据由官方 CLI 按其原生方式保存在 Agent 运行端，并与不同运行服务隔离；桌面不复制其内容。应用只记录可公开展示的登录状态，退出通过官方流程完成。
- 普通配置导出不包含密码、服务令牌、登录凭据和原生会话内容。包含敏感数据的完整备份使用单独入口并说明内容。
- 数据格式升级前保留可恢复副本；损坏数据的备份不得被后续启动覆盖。
- 恢复操作先识别目标数据与覆盖范围，保留现有新数据，不能以“重连”隐式恢复旧备份。
- 卸载、删除项目索引与删除真实项目文件分别处理。

### FR10 多连接与后续完整能力

- 账号：按服务器上的官方 CLI 原生流程管理认证与退出，明确凭据存储位置，不收集用户账号密码代为登录。基础登录状态与登录入口属于首版要求。
- 用量：仅展示工具实际提供的读数，区分 API 费用估算与订阅账单；不支持时显示不可用原因。
- 定时任务：绑定设备、项目、会话和时区；记录计划时间及执行结果，同一计划触发不重复执行。离线后的跳过或补执行策略必须可见。
- 多连接：各连接的会话、凭据和请求相互隔离，公共外观设置可以共用。
- 多设备：操作前明确执行设备；并发回答同一审批时只接受一次有效结果。
- 升级：展示组件版本与兼容性；升级失败保留原版本和数据，运行中的任务有明确的阻止或延后策略。
- 浏览器访问：作为可选独立入口，默认关闭。浏览器不自动拥有本机目录、凭据或执行通道；登录、能力限制和注销由服务端执行。

其中多连接与设备归属为首版要求，跨设备实时审批及其他增强能力按第 3 节安排。

### FR11 项目管理

- 项目具有稳定标识、显示名称、描述、执行方式、运行服务、执行设备与根目录；目录变化与项目改名分别处理。
- 支持搜索、收藏、最近访问、归档和恢复归档。归档只影响管理状态，项目文件和原生会话保留；有运行时先停止或延后归档。
- 项目配置包含默认 Agent、可用模型偏好与项目说明。新会话读取默认值，已运行会话不随设置变更被静默切换。
- 项目下可创建多个会话；各会话保留 Agent 类型、原生标识和执行目标。会话名称与项目名称互不混淆。
- 同一项目被多个会话同时写入时展示并发提示；不承诺通过提示阻止所有文件冲突。
- 支持查看 Git 分支、工作区是否有改动等只读状态；目录不是 Git 仓库时正常使用。自动提交、推送、GitHub Issue/PR 和 worktree 管理列入后续候选。
- 从工作台可定位到对应服务、设备、目录、会话与运行；界面历史和原生上下文缺失时分别显示，不能把项目“在线”当作会话可恢复。

## 7 技术栈与实现约束

Pymss Studio 当前本地工程的前端为 Vue 3、TypeScript、Vite、Naive UI、Pinia、Vue Router、vue-i18n 和 SCSS，使用 pnpm；桌面层为 Tauri 2 与 Rust，另通过 Python Worker 处理音频业务。

新工具以相同的 Vue 与 Tauri 技术体系为基线，不沿用 RemoteShell 的 Go TUI 或 CC Desk Tunnel 的 Electron、React 页面实现。建议采用 Rust 管理桌面系统能力、Python 承接远端连接桥的分工；官方 Agent 程序不改写，具体控制接口经能力验证后确定。

| 层次 | 基线职责 | 仍需明确的边界 |
| --- | --- | --- |
| Vue 前端 | 项目、会话与图形聊天、终端和文件展示、用户输入 | 终端组件与编辑器组件通过验证后选定 |
| Tauri Rust | 本机文件、系统凭据、进程、连接与前端能力边界 | SSH 和临时执行组件的具体集成方式 |
| 远端运行代理 | 持有官方 CLI 进程、转发提示词与审批、整理展示事件和生命周期 | 首选验证 Python 连接桥；SDK 仅为可选适配，不作为必须改用 API key 的理由 |
| Linux 通道与数据服务 | 反向通道、设备绑定、事件持久化与恢复 | 可以与运行代理为同一服务，避免为每个功能拆出独立部署单元 |

以下为技术验证方向，不是已经完成的集成：

```text
Windows 桌面  Vue 图形聊天 → Tauri Rust 连接与系统能力
  ├─ SSH → Linux 运行代理 → Claude 或 Codex → Linux 项目
  └─ WSS → Linux 运行代理 → Claude 或 Codex
                              └─ 反向 SSH 通道 → Windows 本机项目
```

SSH 图形控制可以通过受保护的 SSH 转发访问运行代理；对外服务采用认证与 TLS。原生 Agent 的内部 stdio 或本机监听接口不直接暴露到公网。连接配置应能关联到同一运行服务，避免把同一台服务器误认为多个无关的数据源。

### 7.1 Agent 接入依据与边界

- Codex 的图形适配优先验证官方 app-server：它提供结构化会话、轮次、流式事件与审批，并支持 stdio 传输，适合由运行代理持有子进程。应用不依赖未经保护的公网 Agent 监听接口。[Codex 官方文档](https://learn.chatgpt.com/docs/app-server)
- Claude 的图形适配先验证官方 CLI 的公开结构化输出与控制能力，由服务器进程执行原生 Agent。是否采用官方 SDK 由双向输入、审批、取消和恢复的验证结果决定，不把 SDK 写成已确定的架构。[官方程序化运行说明](https://code.claude.com/docs/en/headless)
- Claude Code 官方认证文档支持用户以自己的账号登录，也说明 SSH 或容器环境下的授权链接与代码回填流程。产品按这一服务端原生登录模式设计，API key 作为用户自选的原生认证方式，不作为强制前提。[官方认证说明](https://code.claude.com/docs/en/authentication)
- Claude Code 的产品集成说明列出了未修改官方二进制、保留认证方式以及由最终用户自行认证等条件；SDK 总览另有第三方产品登录限制。最终接入接口需核验其适用要求，本需求不把“服务器运行官方 CLI”直接等同于“只能使用 API key”。[CLI 产品集成说明](https://code.claude.com/docs/en/legal-and-compliance)、[SDK 说明](https://code.claude.com/docs/en/agent-sdk/overview)
- 上述公开接口存在，并不代表“云端 Agent 经 SSH 操作 Windows”已经验证。两个 Agent 都要实测远程读、写、执行、退出码、取消与审批，尤其不能默认其原生 Linux 文件工具会访问 Windows 项目。
- 优先验证 CC Desk Tunnel 的原生 SSH 调用方式；如需增加执行桥或工具扩展，单独评审能力、原生行为和复杂度，不以未验证的通用协议作为既定实现。

技术实现遵循以下约束：

1. 前端通过声明的命令和事件接口访问本机能力，不拼接任意命令交给后端执行。
2. 终端、图形运行、传输任务分别管理取消与资源关闭；每个请求携带明确目标。
3. 使用成熟的 SSH、终端与存储组件，具体库和版本在兼容性验证后固定。
4. 第三方 AI CLI 与 SDK 的调用方法以当时的官方接口为准，不用终端抓屏伪造结构化能力。
5. Pymss 的音频模型、推理环境、插件市场和素材资源不属于本工具的功能基线。
6. 模型请求、Agent 循环、原生上下文与工具决策由服务器上的官方程序处理。连接桥只提供必要的项目与执行位置指引，不改写官方二进制或用桌面历史重建 Agent。

## 8 状态与异常处理

| 对象 | 主要状态 | 失败后的界面动作 |
| --- | --- | --- |
| SSH 连接 | 未连接、连接中、等待指纹确认、已连接、失败、已断开 | 保留配置，展示失败阶段，允许重新连接 |
| 代理控制连接 | 未连接、连接中、认证中、已连接、重连中、被拒绝 | 保留草稿；被拒绝时要求处理凭据或版本 |
| 执行通道 | 未准备、准备中、探测中、就绪、异常、已关闭 | 控制连接正常时仍显示通道异常并禁止新执行 |
| AI 运行 | 空闲、运行中、等待审批、等待后台任务、停止中、完成、失败、中断 | 保留历史与原因，按原生能力提供继续入口 |
| 文件编辑 | 加载中、已载入、已修改、保存中、保存失败、外部变更 | 保留本地编辑内容并给出重试或比较选择 |
| 后台任务 | 排队、执行中、取消中、成功、失败、已取消 | 显示结果；重试创建可追踪的新尝试 |

错误提示至少说明失败对象、所在阶段与下一步动作。诊断详情保留必要错误码和原因，过滤密码、令牌及项目内容。普通终端输出由用户可见，但不默认整段写入持久日志。

## 9 非功能要求

- 窗口默认参考 Pymss 的 1280 × 820，最小尺寸参考 980 × 680；工作台内容在最小窗口下通过折叠辅助区域保留核心操作。
- 提供浅色、深色和跟随系统主题；布局与终端主题均随设置更新。界面文本以简体中文为默认，按 vue-i18n 管理；英文是否首发完成待版本计划确认。
- 主进程或工作线程承担网络、文件与持续输出处理，前端避免逐字符触发全页面更新。
- 建议性能验收场景：图形会话连续流式输出，辅助终端达到四分屏；终端连续十分钟、合计每秒 200 行、每行约 100 字符。不得因无界缓存持续增加内存。实际耗时阈值在指定测试机后确定。
- 终端回滚与图形历史有界，历史按需加载；缓存上限在详细设计中固定并纳入测试。
- 模态窗口控制焦点并可用键盘完成；状态不能仅靠颜色表达；支持系统缩放与减少动画偏好。
- 关闭页面不泄漏订阅、连接、PTY、进程句柄和定时器。主动退出后只保留明确设计为独立运行的服务端任务。
- 网络或模型不可用时仍可进入设置、查看配置和本地诊断；不把应用启动绑定到第三方服务在线。
- 首版的平台相关文件、凭据存储、PTY 与子进程管理分别封装；Windows 实现不渗入项目和会话的数据模型。macOS 与 Linux 发布前分别完成真实设备或适用系统环境验收。

### 9.1 GitHub 公开发布要求

- 建立独立仓库、清晰的使用文档、架构说明、开发与贡献说明、版本记录和问题反馈模板。
- CI 至少覆盖前端类型与构建、Rust 检查、运行代理与协议测试、秘密扫描及客户端打包检查；涉及尚未发布平台的失败不得被宣传为已支持。
- 桌面、运行代理和协议分别记录版本与兼容范围；不兼容时明确提示，升级包与源码提交可追溯。
- 提供 Windows 安装包与必要的 Linux 运行代理部署说明，发布文件提供校验值，默认不包含个人配置、凭据或会话。
- 发布前确定新仓库许可证并整理实际引入组件的归属与声明；签名、镜像和自动升级按发布计划逐步完善。

| AC16 | 多连接与多设备 | 同时连接两个服务、绑定两台执行设备时，项目、消息、审批和文件操作均指向所选目标 |
| AC17 | Windows 首次安装 | 在无开发环境的受支持 Windows 上按文档安装并完成两种执行方式；组件缺失有明确准备流程 |
| AC18 | 公开发布 | 源码、版本、安装包与校验值对应；发布产物没有个人凭据；未来平台不被标记为已验证支持 |
| AC19 | 官方 CLI 原生运行 | 使用服务器上的官方程序与用户自己的原生登录；桌面不直接请求模型服务、不复制登录令牌；失效时提供重新登录入口 |

## 12 实施前需要验证的技术问题

1. Tauri WebView 中终端输入法、快捷键、粘贴与高频输出是否满足目标 CLI。
2. Rust 如何持有和回收 SSH 会话、本机 SSH 子进程及反向通道；异常退出如何恢复残留状态。
3. 各官方 CLI 的公开控制接口能提供哪些图形能力，能否沿用服务器原生认证，原生终端与图形会话能否共享上下文。
4. 远端项目与本机项目的路径、配置和请求目标如何防止混用；两个运行服务同时指向同一设备目录时如何提示并发。
5. 代理服务的实现语言、数据存储和部署方式，以及是否需要 Python SDK 适配。

上述验证先采用隔离环境和专用目录。涉及真实第三方登录、远端安装、部署或真实项目写入时，按具体操作另行确定执行范围。
