# 待确认问题

当前没有阻止 M0/M1 实施的架构问题。以下事项按保守方案处理，后续阶段再确认：

1. 正式名称与公开仓库地址未确定，继续使用 AgentDesk 代号和 `dev.agentdesk.desktop`，不申请域名、包名或发布产物。
2. 主设计将远端项目索引归于 Host，但本阶段明确不依赖 Host。M1 暂存桌面 SQLite；M2 迁移时保留现有索引、备份和归属，不自动合并不同连接的同名目录。
3. 项目路径与连接归属在创建后固定，修改显示名称和默认项不移动目录。需要更换位置时新建索引并归档旧索引，避免已有终端和编辑器静默切换目标。
4. 任务 02 已提供并运行真实测试服务器验收。该环境禁用公钥认证，本机 agent 服务未运行且未发现 Pageant；真实密钥/agent 验收仍需具备对应条件的环境。不得为了验收修改 sshd 或开启系统服务。
5. 已有关联项目的连接不能修改 host/port/user，应新增连接后新建项目索引；连接名称和认证配置仍可修改。此限制用于保护仍打开的编辑器和项目归属，后续若提供迁移，需要列明影响并确认。
6. 审批默认值本阶段只保存 default/plan。M2 必须根据实际 Agent 能力映射和验证，高权限绕过不从项目文本字段启用。

7. Host/CLI 支持基线仍按设计 glibc ≥ 2.28。测试服务器为 CentOS 7/glibc 2.17；uv 或 Python 能运行不等于整个 Agent 栈受支持，不因此调整架构或扩大产品支持范围。具体 Spike 结果与版本见任务 02 报告。
8. 测试服务器取消反向 streamlocal 监听后保留 socket inode。M3 应对归属明确的 socket 显式取消、确认监听停止并 unlink；断线恢复也须处理旧路径，不能假定 cancel 或 SSH 断线会自动删除文件，不修改全局 StreamLocalBindUnlink。
9. 文件根保护按同 host/port 归集不同连接和用户。不同主机别名是否指向同一服务器尚无法只由字符串证明；M2 的 hostId/身份映射形成前，不擅自合并连接或索引。已有指纹仍严格校验，风险和人工检查写入报告。
10. 测试服务器上 Codex 0.164.0 的单文件部署缺少 bwrap；补齐官方资源后，最小无模型沙箱进程仍在用户命名空间阶段失败。M2 安装器必须检查完整资源和实际执行能力，不能凭版本或 app-server 握手宣布就绪；具体宿主策略原因尚待核验，不修改系统设置，不自动使用 danger-full-access。设计 6.4 的 SSH/Unix socket 权限档位保留待验。
