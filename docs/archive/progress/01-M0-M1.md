## 2. 关键技术决策与假设

1. **不依赖 Host。** M1 项目先存桌面 SQLite，M2 再制定有备份的 Host 迁移方案，不擅自把不同连接的同一路径合并。
2. **版本对齐实际锁文件。** 基线为 Vue 3.5.35、Naive UI 2.44.1、Pinia 3.0.4、Router 4.6.4、i18n 11.4.4、Vite 7.3.3、TS 5.9.3、Sass 1.100.0（SCSS）；Tauri JS API 2.11.0、CLI 2.11.2。新能力依赖单独锁定；Rust 为 russh 0.65.0、russh-sftp 3.0.1、keyring 3.6.3、rusqlite 0.38.0。
3. **身份校验先于认证。** 初次探测连接在 host-key 回调拒绝，UI 确认后重新连接。只接受当前待确认指纹，不能替换已有指纹。没有跳过身份校验选项。
4. **秘密生命周期。** 默认不持久化；勾选保存后只写系统 keyring。为自动重连保留临时内存凭据，断开时取消 supervisor 后释放；没有秘密进入 Pinia、SQLite、设置或日志。
5. **目标固定。** 终端、编辑器和传输保留创建时 Target；新请求使用单调 requestSeq。打开文件后切到别的项目，迟到的首次读取不打开新标签；既有编辑器保存仍更新它自己的资源。连接弹窗换目标会失效旧守卫。
6. **输出有界。** SSH 通道输入队列有界；输出按 16ms/32KiB 合并，通过 8 个帧额度和 `term_ack` 施加背压，避免隐藏窗口导致 IPC 无限积压。rAF 写入 xterm 后释放对应额度，重复 ack 不增加额度。
7. **编辑保存。** UTF-8 上限 2MiB；同目录独占临时文件、复核版本、设置原 mode 后通过远端 `mv` 替换。失败保留本地内容。mtime/size 是乐观检查，不是文件锁，不保证抵御完全并发写入。
8. **保守权限。** 项目路径与连接归属创建后固定；关联项目的连接不得改 host/port/user。默认审批只保存 default/plan，M2 根据真实 CLI 能力重新验证，不自动下发高权限。
9. **平台隔离。** Windows agent 管道与 Pageant 位于 `platform/windows.rs`，Unix 使用 SSH_AUTH_SOCK；凭据统一 keyring。macOS/Linux 未声明为已验收客户端。
10. **生成器边界。** 使用标准库实现当前 JSON Schema 子集，未知类型报错，生成三端样例；不把类型声明当作完整运行时校验。协议帧限制、业务方法和 Host 生命周期属于 M2。

其他开放事项见 `docs/QUESTIONS.md`。

## 3. S1：russh streamlocal 与 Pageant 的实际结论

依据是 `Cargo.lock` 锁定并实际编译的 **russh 0.65.0 源码**及本机协议测试，不仅依据网络搜索中的旧版本文档。

| 能力 | 实际 API／结果 | 尚缺验证 |
| --- | --- | --- |
| 正向 streamlocal | `channel_open_direct_streamlocal` 存在；`ssh/forward.rs` 封装；本地服务完成通道打开和字节传输。 | Ubuntu/OpenSSH 的真实 Unix socket 权限与路径。 |
| 反向 streamlocal | `streamlocal_forward`、`cancel_streamlocal_forward`、客户端 `server_channel_open_forwarded_streamlocal` 回调均存在。已验证反向请求/取消的真实 SSH 报文交换。 | 测试服务只确认请求，没有绑定真实 Unix socket；尚未验证服务器主动回连、权限 0600 与 Windows 本机 sshd 对接。 |
| Windows OpenSSH agent | 源码 `keys/agent/client.rs` 提供 `connect_named_pipe`；平台模块连接 OpenSSH 标准命名管道并设置超时。 | 用户真实 agent 的密钥枚举、确认和签名。 |
| Pageant | 同一源码提供 `connect_pageant`，使用 pageant 0.2.5 的 PageantStream；平台模块已提供独立选择。 | 实际 Pageant 进程、锁定/解锁、密钥和签名确认。 |

因此：**当前版本的 russh 并不缺少这些 API，无需先退回系统 ssh.exe 或 TCP 方案；S1 只能判定部分通过。** `forward.rs` 是实际接口封装，不是 M3 的完整转发器。官方包入口为 [russh 0.65.0](https://crates.io/crates/russh/0.65.0)，具体源码路径和锁定版本可在 cargo 下载的 crate 中复核。

## 6. 已知问题与下一步

1. **验收缺口优先于 M2。** 建议先完成 agent/Pageant、真实 Linux shell/tar、IME 和通知点击的最小手工矩阵，再开始 Host 安装及图形会话。
2. **文件语义限制。** 保存保持纯 CRLF 和 POSIX mode；混合换行编辑后可能统一为 LF。原子替换不保证保留硬链接关系、所有权、ACL 或扩展属性，敏感目录需要针对实际服务器验证；不是远端文件锁。
3. **远端临时包。** 正常完成/失败/取消通过 shell trap 清理；客户端或服务器被强杀、服务器断电时不能保证 trap 执行，需要检查残留。正常应用退出会等待已归属传输清理。
4. **组件体积。** 终端与编辑器已懒加载；CodeMirror 及语言/merge 组件仍有大 chunk，后续可按语言进一步拆分。没有为了消除提示提高警告阈值。
5. **连接和索引迁移。** 已关联项目的连接目标、项目目录不能直接改写；后续迁移能力需要单独列出影响并确认。当前没有自动合并远端索引或同步到第二台设备。
6. **M2/M3 未做。** Host 业务、会话/运行/审批、官方 CLI 登录适配、本机项目、本机 PTY/sshd/执行通道全部未实现；环境和聊天页面明确说明阶段。
7. **发布检查未做。** GitHub Actions 未实际运行，NSIS、签名、完整依赖许可清单、升级及多平台发布均未验收。本次未推送远程仓库或部署服务。
